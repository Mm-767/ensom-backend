## 제출 성공 기준

```
이메일/Google 로그인 → 약관 동의·초기 설정 → 캘린더/직접 일정 생성 → 경로·환경 조회
→ 준비 시작·출발·도착 계획 → 시간 알림·웰니스 행동 → 원탭 행동 기록 → 다음 계획 개인화 보정
```

## FE 핵심 규칙

### API 계약

- 요청·응답은 **camelCase**
- 모든 시각은 **오프셋 포함 ISO-8601** (Z만 거부)
- 모든 쓰기에 `Idempotency-Key` 헤더 필수
- 행동 이벤트에 `clientEventId` (UUID) 필수
- 계획 응답에는 `breakdown`, `reasons`, `degraded`가 항상 포함
- `planStatus`(active/superseded) ≠ `eventStatus`(planned→…→closed) — 별개 생명주기

### 오프라인 · 멱등성

- Drift 기반 영속 오프라인 큐 — 앱 킬·재시작 후에도 재전송
- `clientEventId` UNIQUE → 중복은 오류가 아니라 정상 (`duplicated` 카운트)
- 네트워크 오류(`retryable: true`)면 로그인 화면으로 보내지 않고 재시도

### 로컬 알림 이중화 (TR-07)

- 준비 시작(`prepStartAt`) + 출발 임박(`recommendedDepartAt`) 2건 로컬 예약
- 서버 푸시가 먼저 도착 시 같은 `dedupKey`의 로컬 알림 취소
- 돌발·웰니스는 예측 불가이므로 서버 푸시 단독

### 지오펜스 (TR-08)

- 활성 계획 1건 · 리전 2개 (출발지 EXIT + 목적지 ENTER)
- iOS 20개 한도 → 조용한 초과 방지
- **좌표 미전송** — 판정 결과(actionType, confidence)만 서버로
- 콜백 안에서 네트워크 대기 금지 → 로컬 DB 기록 후 즉시 반환, 동기화는 WorkManager

### 민감 정보 (TR-10)

- `isSensitive: true` 항목은 잠금화면·푸시에서 일반화 문구(body_masked)로 치환
- 로그아웃 시 토큰·민감 캐시·예약 로컬 알림 소거
- Keychain / EncryptedSharedPreferences에만 토큰 보관

### 표시명 처리

- 클라이언트는 **`displayName` 하나만** 읽으면 됨
- 해석 순서는 서버가 처리: displayLabel → destinationName → "오후 2시 일정"

## 범위 가드레일

### P0 — 반드시 구현

- 로그인·동의·일정·계획·계산 근거
- 맞춤 준비 항목과 시간 소요 루틴
- 기본 경로 3종과 카카오맵 렌더
- 시간 알림, 행동 기록, 오프라인 멱등성
- 원인 분리 개인화의 최소 순환
- WIS와 최대 3개 웰니스 행동
- 민감 정보 마스킹과 삭제 수명주기

### 핵심 흐름이 위험할 때 뒤로 미룸

- 유형별 개인화 모델
- 조건부 맞춤 준비 규칙 자동 적용
- 일일 카드 고급 통계와 주간 리포트
- Apple 로그인

### 구현하지 않음

- 지도 환경 레이어와 센서 시각화
- 자체 경로 점수와 복잡한 지도 인터랙션
- 건강 진단·치료·효능·피부 판단
- 외부 캘린더 제목 원문 장기 보관
- 하루 전체 위치·이동 경로 저장
