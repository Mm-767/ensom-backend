# Ensom 화면 연결 명세서 v1.0

작성일 2026-08-19 · 기준 문서 PRD v0.4.3 · 화면설계서 v1.0 · 프로토타입 27개 파일

---

## 0. 이 문서를 읽는 법

프론트엔드 구현 시 **라우팅과 화면 전이**를 판단하기 위한 문서다. 각 화면마다 아래 네 가지를 정의한다.

| 항목 | 뜻 |
|---|---|
| **진입** | 이 화면으로 들어오는 모든 경로 |
| **액션 → 목적지** | 화면 안의 어떤 요소를 조작하면 어디로 가는가 |
| **뒤로** | 뒤로가기 / 닫기를 눌렀을 때 어디로 가는가 |
| **조건·예외** | 진입 차단, 상태 분기, 되돌아오기 금지 등 |

**표기 규칙**

- `S-xx` — 화면 ID. `S-01`~`S-15`는 기존 화면설계서와 번호가 같다. `S-16` 이상은 이번에 추가된 화면.
- `[탭]` — 하단 탭바로 이동. 스택을 쌓지 않고 탭을 전환한다.
- `[푸시]` — 스택에 쌓임. 뒤로가기로 직전 화면에 돌아온다.
- `[시트]` — 하단에서 올라오는 모달. 뒤로가기/스크림 탭으로 닫히고 뒤에 있던 화면이 그대로 유지된다.
- `[교체]` — 스택을 비우고 갈아탄다. 뒤로가기로 돌아올 수 없다.
- `[전역]` — 어느 화면에서든 발생할 수 있다.

## 1. 전역 규칙

### 1.1 앱 진입 분기

```
앱 실행
  └─ S-37 스플래시  (세션 검사 중, 최대 약 1.5초, 인터랙션 없음)
       ├─ 세션 유효 + 필수 약관 완료 ────────────→ [교체] S-06 홈
       ├─ 세션 유효 + 필수 약관 미완료 ──────────→ [교체] S-02 약관 동의   ※ 약관 개정 시
       └─ 세션 없음 / refresh 실패 ─────────────→ [교체] S-01 로그인
```

- 스플래시는 온보딩 단계가 아니다. **앱을 켤 때마다** 뜬다.
- 네트워크 오류로 세션 검사에 실패한 경우 **로그인 화면으로 보내지 않는다.** 스플래시에 재시도 안내를 띄우고 머문다. (`retryable: true`)
- 스플래시에는 슬로건을 넣지 않는다. 슬로건은 S-01 로그인에서 처음 노출된다. 두 화면이 시각적으로 겹쳐 화면이 두 번 뜨는 것처럼 보이는 것을 막기 위함이다.

### 1.2 탭 구조

로그인 + 필수 약관 완료 이후에만 접근 가능하다. 탭은 4개이며 각 탭은 **독립 스택**을 가진다.

| 탭 | 루트 화면 |
|---|---|
| 캘린더 | S-09 |
| 홈 | S-06 (앱 기본 탭) |
| 지도 | S-08 |
| 프로필 | S-14 |

- 탭 전환 시 각 탭의 스택 상태(스크롤 위치, 열어둔 시트)는 유지된다.
- 전면 가로 스와이프 전환은 지원하지 않는다. (지도 제스처와 충돌)
- **탭바를 숨기는 경우**: 전체화면 오버레이(S-01·S-02·S-16~S-20·S-34~S-37), 온보딩 전체, 시트가 전체 높이로 펼쳐진 경우.

### 1.3 진입 차단 게이트

| 게이트 | 차단 대상 | 통과 조건 |
|---|---|---|
| 인증 | 홈·지도·캘린더·프로필 전부 | 로그인 성공 |
| 필수 약관 | 홈·지도·캘린더·프로필 전부 | `consentRequired`가 빈 배열 |

- 비회원·게스트 모드는 없다.
- 필수 약관 미동의 상태에서는 S-02에서 **뒤로 나갈 수 없다.** 건너뛰기 버튼을 두지 않는다. 이 게이트만이 유일하게 진행을 강제 차단한다.
- 권한(위치·알림·캘린더)은 **게이트가 아니다.** 거부해도 앱은 정상 동작하며, 인라인 배너로 알리고 대체 수단을 안내한다. (§5 참조)

### 1.4 뒤로가기 기본 규칙

1. 시트가 열려 있으면 → 시트를 닫는다.
2. 스택에 이전 화면이 있으면 → 그 화면으로 돌아간다.
3. 탭 루트에 있으면 → 홈 탭으로 이동한다.
4. 홈 탭 루트에 있으면 → 앱을 종료한다. (Android는 한 번 더 눌러 확인)

**뒤로가기를 막아야 하는 화면**: S-02(필수 약관 미완료 시), S-18 가입 완료, S-42 온보딩 완료. 이 화면들은 이전 단계로 되돌아가는 것이 의미가 없거나 상태를 깨뜨린다.

- 제공자는 **이메일 + Google 두 가지만**이다. (TRD D2 확정)
- `계속하기`는 이메일·비밀번호 두 필드가 모두 채워졌을 때만 활성화한다.

#### 3.1 로그인 후 분기

```
로그인 성공
  ├─ consentRequired 비어있지 않음 ──→ [교체] S-02 약관 동의
  ├─ 온보딩 미완료 ────────────────→ [교체] S-03 준비 시간   ※ 온보딩 이어서
  └─ 온보딩 완료 ─────────────────→ [교체] S-06 홈
```

### S-01E 로그인 오류

세 상태 모두 **S-01 위에 얹히는 배너**다. 별도 화면으로 전환하지 않는다.

| 오류 | 표시 | 액션 |
|---|---|---|
| 로그인 취소 | 담백한 한 줄 안내. 경고색·아이콘 없음 | 없음. 화면 유지 |
| 네트워크 오류 | surface-2 배너 + `다시 시도` | 재시도 → 인증 재요청 |
| 제공자 오류 | caution 세로바 배너 + `다시 시도` | 재시도 / 다른 방법으로 로그인 |

**조건·예외** — 어떤 오류에서도 로그인 버튼은 화면에 그대로 남아 있어야 한다. 전면 오류 화면으로 갈아치우지 않는다.

### S-16 회원가입

| | |
|---|---|
| **진입** | S-01 `회원가입` 링크 |
| **뒤로** | S-01 |

| 액션 | 전이 |
|---|---|
| 닉네임 `중복확인` | 인라인 결과 문구 표시. 화면 이동 없음 |
| 이메일 `중복확인` | 인라인 결과 문구 표시. 화면 이동 없음 |
| `인증메일 발송` | 카드가 발송됨 상태로 전환 + 카운트다운 시작. 화면 이동 없음 |
| 약관 행의 `보기 ›` | [푸시] S-21 (해당 약관) |
| `회원가입` | [교체] S-17 이메일 인증 |
| `Google 계정으로 가입` | 인증 성공 → [교체] S-02 |
| `로그인` 링크 | [뒤로] S-01 |

**조건·예외**

- `회원가입` 활성화 조건: 이름·닉네임·이메일·비밀번호·비밀번호 확인이 모두 입력 + 비밀번호 8자 이상 + 확인 일치 + **필수 약관 2개 체크**.
- 이 화면은 약관 동의를 **폼 안에 인라인으로** 포함한다. 이메일 가입 경로에서는 S-02를 따로 거치지 않는다.
- Google 가입은 약관 동의를 받을 자리가 없으므로 **S-02를 반드시 거친다.**

## 5. 권한 상태별 분기

권한은 게이트가 아니다. 거부 시 **전면 차단 대신 인라인 배너 + 대체 수단**을 제공한다.

| 권한 | 거부 시 대체 수단 | 배너 위치 |
|---|---|---|
| 위치 | `출발했어요` 직접 탭 · 도착 후 1탭 확인 | S-06 홈, S-08 지도, S-12 상세 |
| 알림 | S-06 홈 카드에서 준비 시각 직접 확인 | S-06 홈 |
| 캘린더 | S-10에서 일정 직접 생성 | S-09 캘린더 |

```
기능 사용 시도
  └─ 권한 상태 확인
       ├─ 허용 ──────→ 기능 실행
       ├─ 미결정 ────→ S-34 프라이밍 → OS 다이얼로그
       └─ 거부 ──────→ S-35 거부 안내
                          ├─ [설정에서 켜기] → S-36 OS 설정 안내 → OS 설정 앱
                          └─ [지금은 괜찮아요] → 대체 수단으로 계속 진행
```

**배너 규칙** — 사용자가 배너를 닫으면 그 세션 동안 다시 띄우지 않는다.

## 6. 구현 시 주의할 전이

프로토타입을 만들며 확정된, 놓치기 쉬운 규칙들이다.

1. **S-08R → S-10 프리필** — 출발지·목적지·시각·선택 경로를 넘긴다. 사용자에게 다시 입력받으면 안 된다. (`sourceType=map_search`)
2. **S-11 `잘 모르겠어요`** — 상태를 강제로 확정하지 말고 미해결로 남긴다. 재질문 금지.
3. **S-02 뒤로가기** — 필수 약관 미완료 상태에서 나갈 수 있으면 게이트가 무너진다.
4. **네트워크 오류로 로그인 화면에 보내지 않기** — 세션 검사 실패와 인증 실패를 구분해야 한다.
5. **S-25 비밀번호 변경 후** — 다른 기기 세션을 무효화한다. 현재 기기는 유지한다.
6. **S-27 마지막 로그인 수단** — 해제 버튼을 비활성화한다. 계정에 접근할 수 없게 된다.
7. **S-32는 값을 반환하는 시트** — 자체적으로 화면을 전환하지 않는다. 호출한 화면이 결과를 받아 처리한다.
8. **S-05 고정 안내 문구** — 기능을 꺼도 사라지면 안 된다. 기능 카드 바깥에 배치한다.
9. **동기화 일부 실패** — 전면 오류로 막지 않는다. 가진 데이터는 계속 보여준다.
10. **코치마크** — 최대 2개, 한 번에 하나씩, 최초 1회만.
