# Ensom 화면설계서 v2.0
> **문서 상태(2026-08-20):** 이 문서는 기능별 ID 체계의 이력·상세 참고용이다. 최신 화면 전이와 신규 S-16~S-44 범위는 `02_화면연결_명세서_v1.0.md`, 실제 구현·BE 갭은 `09_0820_화면연결_구현대조.md`를 우선한다.

> 기준 문서: **PRD v0.4.3** · API 매핑은 API 명세서 v5.0 기준 · HTML 프로토타입: `ensom_master_flow_bundle/`
> 디자인 키워드: 서양식 미니멀 · 쿨톤 · 넓은 여백 · 선명한 타이포 · 정보 우선순위가 명확한 카드 (PRD §21.1)
> 공통: 색상 단독 상태 구분 금지, 드래그에는 버튼 대안, 재촉·평가하지 않는 카피 톤 (PRD §21.4, §21.6)

> **상태(로딩·빈상태·에러·성공·권한요청·확인모달) 전수 체크리스트는 `08_화면상태_체크리스트.md` 참고.** 이 문서의 각 화면 "상태" 항목은 대표 상태만 적었고, 개발 착수 전 빠짐없는 목록은 그쪽이 원본이다.

## v2.0 변경 사항 (v1.0 대비)

- **화면 ID 체계 전면 교체**: `S-01~S-15` 순번 → **기능별 고유 접두사**(`HM`, `CAL`, `MAP`, `PRF`, `ONB`, `DTL`, `RTE`, `PICK`, `PREP`, `SRCH`, `SYS`). 코드만 보고 어느 화면인지 바로 알 수 있게 함.
- **4번째 탭 "설정" → "프로필"로 통일**, 탭 순서 확정: **캘린더 · 홈 · 지도 · 프로필** (HTML 프로토타입·화면설계서 기준. PRD §21.5 원문 "홈·지도·캘린더·설정"은 폐기 — `02_IA.md` C-반영 완료)
- 모든 화면에 **HTML 프로토타입 파일 매핑**을 추가(있으면 파일명, 없으면 "❌ 미제작").
- 모든 화면에 **버튼/카드 → 다음 화면 ID** 매핑을 추가. HTML에서 실제로 연결이 구현된 것과, 스펙상 그래야 하는데 프로토타입엔 아직 안 붙어 있는 것("⚠ 미구현")을 구분 표기.
- 프로필(구 설정) 하위 6개 화면을 각각 독립 ID로 분리(`PRF-02~09`) — 기존엔 S-14 하나에 뭉쳐 있었음.
- 지금까지 화면설계서에 번호가 없던 공용 화면 6종에 새 ID 부여: 일정 상세(`DTL-01`), 경로 변경(`RTE-01`), 날짜·시간·소요시간 피커(`PICK-01~03`), 준비 항목 추가 시트(`PREP-01`), 장소 검색(`SRCH-01~02`).
- 전면 차단 화면 4종(`SYS-01~04`) 신규 등재 — v1.0엔 아예 없었음.

## 1. 화면 ID 접두사 표

| 접두사 | 의미 | 소속 | 개수 |
|---|---|---|---|
| `ONB` | 온보딩 · 인증 | 로그인 전~최초 1회 | 11 |
| `HM` | 홈 (하단 탭 ②) | 탭 | 4 |
| `CAL` | 캘린더 (하단 탭 ①) | 탭 | 6 |
| `MAP` | 지도 (하단 탭 ③) | 탭 | 1 |
| `PRF` | 프로필 (하단 탭 ④, 구 "설정") | 탭 | 9 |
| `DTL` | 일정 상세 — 홈·캘린더 공용 진입 | 공용 | 1 |
| `RTE` | 경로 변경 후보 시트 — 일정상세·홈 공용 | 공용 | 1 |
| `PICK` | 날짜·시간·소요시간 피커 시트 — 여러 폼에서 호출 | 공용 컴포넌트 | 3 |
| `PREP` | 준비 항목 추가 시트 — 홈·상세·온보딩 공용 | 공용 컴포넌트 | 1 |
| `SRCH` | 장소 검색 — 지도·일정생성·주요장소 공용 | 공용 | 2 |
| `SYS` | 전면 차단 화면(네트워크/세션/점검/업데이트) | 시스템 | 4 |

**표기 규칙**: `[접두사]-[두자리 번호]`. 번호는 그 접두사 안에서의 진입/흐름 순서를 따른다(우선순위 아님). 상태 배리에이션(빈 상태·오류·오프라인 등)은 별도 ID를 만들지 않고 **해당 화면 ID의 "상태" 항목**으로 문서화한다(예: 일정 없음은 `HM-01`의 한 상태이지 `HM-05`가 아님).

**탭 순서(확정)**: 캘린더(`CAL`) · 홈(`HM`) · 지도(`MAP`) · 프로필(`PRF`). 앱 실행 기본 진입은 `HM-01`.

### DTL-01 일정 상세

| 항목 | 내용 |
|---|---|
| 목적 | 계획 전체·근거·체크리스트·결과를 한 곳에서 확인·수정 |
| 요구사항 | PLAN-02~05, REPORT-01, WELL-03 |
| HTML | ✅ `ensom_detail.html` — 결과 섹션에 4가지 판정 유형(정시/촉박/지각-원인명확/지각-원인불분명)을 전부 포함(구 `ensom_result_eval.html`은 참고용으로만 보존) |

**구성**
1. 헤더: 표시명·시간·목적지·상태
2. 시간 계획: 준비시작/출발/도착 + breakdown(개인준비·환경가산·루틴·이동·교통버퍼·도착여유)
3. 계산 근거 리스트: "개인 준비 시간 35분: 최근 8회 기록 기준, 초기 설정보다 +5분" 등
4. 체크리스트: 맞춤 항목(완료 토글) + 웰니스 행동(이유 동반, 완료/해제)
5. 경로: 선택 경로 + [경로 변경] → `RTE-01`
6. 계획 수정: 준비·출발 시각, 출발지 직접 수정(새 리비전)
7. (종료 후) 결과 섹션: 정시/촉박/지각·실제 편차·지연 원인·사후 평가 입력(판정 확실하면 질문 미노출)
8. WIS 점수 밴드 표시하되 "건강 점수 아님", 숫자 강조 금지

**API**: `GET /events/{id}/plans/latest` · `PATCH /plans/{id}` · `POST /events/{id}/plan/recalculate` · `GET /events/{id}/execution` · `POST /events/{id}/feedback`
